## 1. 文档概述

### 1.1 背景

高等教育质量监测需要采集覆盖学生、教师、教学、科研、资产等多维度的数据。传统手工填报方式存在以下痛点：

- **数据重复录入**：同一数据在多个业务系统中已存在，仍需人工二次录入质量监测系统
- **时效性滞后**：年度/学期数据统计依赖期末集中填报，无法实现动态监测
- **准确性差**：人工填报易产生错误，跨系统数据一致性难以保障
- **工作负担重**：教务、人事等部门需投入大量人力进行数据整理与报送

### 1.2 目标

构建自动化数据对接能力，实现校内主流业务系统与质量监测平台的数据贯通：

| 目标维度 | 具体目标 | 衡量指标 |
|---------|---------|---------|
| 覆盖率 | 核心业务系统数据自动采集 | 教务、人事、科研、学工系统100%对接 |
| 时效性 | 数据更新延迟控制在合理范围 | T+1日同步（日增量），T+7日全量校验 |
| 准确性 | 自动采集数据准确率 | 关键字段准确率≥99.5% |
| 效率提升 | 相比手工填报效率提升 | 数据准备时间减少80%以上 |

### 1.3 范围界定

**包含范围**：
- 教务管理系统（课程、培养方案、排课、成绩、学籍）
- 人事管理系统（教师基本信息、职称、学历、工作量）
- 科研管理系统（论文、项目、专利、获奖）
- 学工管理系统（学生奖惩、资助、活动、心理健康）
- 就业管理系统（就业单位、薪资、跟踪调查）
- 财务/资产系统（教学经费、设备资产）

**不包含范围**（后续版本规划）：
- 校外系统对接（教育部、省级平台上行对接在"开放集成层"实现）
- 非结构化数据智能识别（OCR/NLP在"半自动化采集"模块实现）
- 实时流数据处理（秒级/分钟级同步，本期暂不支持）

## 2. 术语定义

| 术语 | 定义 |
|-----|------|
| **数据源** | 提供原始数据的业务系统，如教务系统、人事系统等 |
| **数据目标** | 接收数据的 destination，即质量监测平台数据仓库 |
| **ETL** | Extract-Transform-Load，数据抽取-转换-加载过程 |
| **CDC** | Change Data Capture，变更数据捕获技术 |
| **ODS** | Operational Data Store，操作数据存储，贴源层 |
| **主数据** | 跨系统共享的核心实体数据，如学生、教师、组织机构 |
| **增量同步** | 仅同步自上次同步以来新增或变更的数据 |
| **全量同步** | 同步全部数据，通常用于首次初始化或周期性校验 |

## 3. 用户故事与需求

### 3.1 用户画像

#### 用户角色1：数据管理员（教务处/人事处信息科）
- **痛点**：每学期末需要整理大量Excel向质量监测平台报送
- **期望**：配置一次后自动同步，只需处理异常数据
- **使用频率**：每周查看同步状态，每月处理异常

#### 用户角色2：系统管理员（信息中心）
- **痛点**：各业务系统厂商接口不统一，对接开发成本高
- **期望**：标准化对接框架，降低开发和维护成本
- **使用频率**：系统上线时配置，日常监控运行状态

#### 用户角色3：质量办负责人
- **痛点**：不知道数据是否最新，不敢直接使用
- **期望**：数据血缘清晰，更新时效可见，质量可信赖
- **使用频率**：每日查看数据 freshness

### 3.2 用户故事

#### US-001：数据源配置
> 作为系统管理员，我希望通过可视化界面配置数据源连接，以便快速接入新的业务系统。

**验收标准**：
- 支持MySQL、Oracle、SQL Server、PostgreSQL等主流数据库
- 支持通过JDBCURL、主机+端口+库名两种方式配置
- 连接信息加密存储，支持测试连接可用性
- 每个数据源独立配置同步策略（频率、时间窗口）

#### US-002：数据表映射配置
> 作为数据管理员，我希望通过拖拽方式将业务系统表字段映射到标准字段，无需编写SQL。

**验收标准**：
- 自动读取源表结构（表名、字段名、字段类型、注释）
- 提供标准字段库（内置300+标准字段定义）
- 支持字段级映射配置（一对一、一对多、多对一、常量填充、公式计算）
- 支持字段转换规则（编码转换、日期格式统一、单位换算）
- 映射配置支持导入导出，便于多环境迁移

#### US-003：增量数据同步
> 作为数据管理员，我希望系统每天自动同步增量数据，减少全量同步对业务系统的压力。

**验收标准**：
- 支持基于时间戳字段的增量识别（update_time）
- 支持基于自增ID的增量识别
- 支持CDC日志解析（MySQL binlog、Oracle LogMiner）
- 增量同步失败支持断点续传
- 同步结果通知（成功/失败/异常数据条数）

#### US-004：数据质量校验
> 作为质量办负责人，我希望在数据入库前自动校验质量，防止脏数据污染。

**验收标准**：
- 支持完整性校验（必填项、外键关联）
- 支持格式校验（身份证号、手机号、邮箱正则）
- 支持范围校验（数值范围、日期范围）
- 支持逻辑校验（入学日期<毕业日期、成绩0-100）
- 校验失败数据进入"待清洗区"，不进入正式库

#### US-005：同步任务监控
> 作为系统管理员，我希望实时监控所有同步任务的运行状态，及时发现并处理问题。

**验收标准**：
- 任务看板：展示所有任务状态（运行中/成功/失败/未启动）
- 实时日志：查看任务执行日志，支持关键字搜索
- 异常告警：失败任务自动通知（站内信/邮件/企业微信）
- 历史追溯：保留30天任务执行历史

#### US-006：数据血缘追溯
> 作为质量办负责人，我希望查看任意数据的来源和流转路径，建立数据可信度。

**验收标准**：
- 字段级血缘：展示某标准字段来源于哪些源系统字段
- 表级血缘：展示数据从ODS→DWD→DWS→ADS的流转
- 可视化图谱：图形化展示数据血缘关系
- 影响分析：修改源字段时，提示会影响哪些下游指标

## 4. 功能详述

### 4.1 数据源管理模块

#### 4.1.1 数据源列表

**功能描述**：管理所有已对接的业务系统数据源

**界面元素**：
- 列表展示：数据源名称、类型（数据库/API/文件）、状态、最后同步时间、操作按钮
- 搜索筛选：按名称、类型、状态筛选
- 批量操作：批量启用/禁用、批量删除

**数据模型**：

```
数据源表（data_source）
├── id: 主键
├── name: 数据源名称（如"正方教务系统"）
├── type: 类型（MYSQL/ORACLE/SQLSERVER/POSTGRESQL/API/FILE）
├── status: 状态（ENABLED/DISABLED/ERROR）
├── connection_config: 连接配置（JSON加密存储）
│   ├── host: 主机地址
│   ├── port: 端口
│   ├── database: 数据库名
│   ├── username: 用户名
│   ├── password: 密码（加密）
│   └── params: 连接参数
├── sync_strategy: 同步策略（JSON）
│   ├── mode: 同步模式（FULL/INCREMENTAL）
│   ├── frequency: 频率（HOURLY/DAILY/WEEKLY）
│   ├── time_window: 时间窗口（如"02:00-06:00"）
│   └── retry_times: 失败重试次数
├── last_sync_time: 最后同步时间
├── last_sync_status: 最后同步状态
├── created_at: 创建时间
└── updated_at: 更新时间
```

**业务规则**：
- 数据源名称全局唯一，不可重复
- 删除数据源前需确认无关联的同步任务
- 禁用数据源后，关联的定时任务自动暂停

#### 4.1.2 新建数据源

**操作流程**：
1. 选择数据源类型（数据库/API/文件）
2. 填写连接信息（根据类型动态展示表单）
3. 点击"测试连接"验证可用性
4. 配置同步策略（频率、时间窗口）
5. 保存并自动加载表结构

**异常处理**：
- 连接超时：提示"连接超时，请检查网络或防火墙设置"
- 认证失败：提示"用户名或密码错误"
- 权限不足：提示"当前账号缺少SELECT权限，请联系DBA授权"

#### 4.1.3 数据源详情

**功能描述**：展示数据源基本信息、连接测试记录、关联任务列表、操作日志

**界面元素**：
- 基本信息卡片：名称、类型、状态、创建人、创建时间
- 连接信息（脱敏展示）：主机、端口、数据库名（密码显示为******）
- 表结构浏览：展示该数据源下所有表及字段信息
- 关联任务：使用该数据源的所有同步任务
- 操作日志：对该数据源的配置变更记录

### 4.2 数据映射配置模块

#### 4.2.1 同步任务管理

**功能描述**：管理数据从源到目标的同步任务

**数据模型**：

```
同步任务表（sync_task）
├── id: 主键
├── name: 任务名称
├── source_id: 数据源ID（外键）
├── source_table: 源表名
├── target_table: 目标表名（ODS层表）
├── mapping_config: 字段映射配置（JSON）
│   └── mappings: 字段映射数组
│       ├── source_field: 源字段名
│       ├── target_field: 目标字段名
│       ├── transform_rule: 转换规则（可选）
│       └── is_primary_key: 是否主键
├── filter_condition: 过滤条件SQL片段（可选）
├── sync_mode: 同步模式（FULL/INCREMENTAL）
├── incremental_field: 增量标识字段（增量模式必填）
├── schedule_config: 调度配置（JSON）
│   ├── type: 调度类型（CRON/INTERVAL）
│   ├── expression: CRON表达式或间隔分钟数
│   └── timezone: 时区
├── status: 任务状态（RUNNING/PAUSED/ERROR）
├── created_at: 创建时间
└── updated_at: 更新时间
```

**业务规则**：
- 任务名称在同一数据源下唯一
- 增量同步必须指定增量标识字段（时间戳或自增ID）
- 支持暂停/恢复任务，暂停期间不执行调度
- 删除任务前需确认无正在运行的实例

#### 4.2.2 可视化映射配置器

**功能描述**：拖拽式配置源表字段与标准字段的映射关系

**界面布局**：
```
┌─────────────────────────────────────────────────────────────┐
│  源表字段（左）        映射关系（中）       标准字段（右）    │
│  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐   │
│  │ □ student_id│────→│ 主键映射    │←────│ □ 学号       │   │
│  │ □ name      │────→│ 直接映射    │←────│ □ 姓名       │   │
│  │ □ gender    │────→│ 编码转换    │←────│ □ 性别       │   │
│  │ □ birthday  │────→│ 日期格式化  │←────│ □ 出生日期   │   │
│  │ □ dept_code │────→│ 关联映射    │←────│ □ 学院代码   │   │
│  └─────────────┘     └─────────────┘     └─────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**支持的映射类型**：

| 映射类型 | 说明 | 示例 |
|---------|------|------|
| 直接映射 | 字段一对一复制 | source.name → target.姓名 |
| 编码转换 | 值域映射 | source.sex(1/2) → target.性别(男/女) |
| 日期格式化 | 统一日期格式 | source.birth(2020/1/1) → target.出生日期(2020-01-01) |
| 字符串处理 | 截取、拼接、替换 | source.name(张三001) → target.姓名(张三) |
| 数值计算 | 单位换算、聚合 | source.score(85.5) → target.成绩(86)四舍五入 |
| 常量填充 | 固定值 | target.数据来源 = "教务系统" |
| 关联查询 | 关联其他表取值 | source.dept_code → 关联院系表 → target.学院名称 |

#### 4.2.3 转换规则引擎

**规则配置界面**：
- 规则类型选择器（下拉选择上述映射类型）
- 规则参数配置面板（根据类型动态变化）
- 实时预览：输入测试数据，展示转换结果
- 规则验证：保存前验证规则语法正确性

**内置规则模板**：
- 性别编码转换（1→男，2→女，9→未知）
- 日期格式统一（yyyy/MM/dd → yyyy-MM-dd）
- 身份证号码脱敏（保留前6位和后4位）
- 手机号脱敏（保留前3位和后4位）

### 4.3 数据同步引擎

#### 4.3.1 同步调度器

**功能描述**：负责任务的调度执行

**技术方案**：
- 调度框架：XXL-JOB / DolphinScheduler（推荐）
- 任务分片：大数据量任务支持分片并行执行
- 失败重试：支持配置重试次数和重试间隔（指数退避）
- 任务依赖：支持配置任务间的依赖关系（如必须先完成学生表同步才能同步成绩表）

**调度策略**：

| 策略类型 | 适用场景 | 配置示例 |
|---------|---------|---------|
| 定时触发 | 固定周期同步 | 每天凌晨2点执行 |
| 间隔触发 | 高频增量同步 | 每30分钟执行一次 |
| 事件触发 | 实时性要求高 | 监听数据库binlog变更 |
| 手动触发 | 首次初始化或异常修复 | 管理员手动点击执行 |

#### 4.3.2 数据抽取策略

**全量同步**：
- 适用场景：首次初始化、数据结构变更、周期性全量校验
- 实现方式：SELECT * FROM source_table WHERE 过滤条件
- 优化措施：
  - 大数据量分批次读取（每次10000条）
  - 使用数据库游标避免内存溢出
  - 目标表先写入临时表，完成后原子切换

**增量同步**：
- 适用场景：日常数据更新，减少系统压力
- 实现方式：
  - 时间戳方式：WHERE update_time > #{last_sync_time}
  - 自增ID方式：WHERE id > #{last_max_id}
  - CDC方式：解析数据库日志捕获变更
- 冲突处理：
  - 主键冲突：更新目标表（UPSERT）
  - 删除感知：软删除标记或物理删除（可配置）

#### 4.3.3 数据加载策略

**写入模式**：
- INSERT：仅插入新数据（适用于追加型数据）
- UPSERT：存在则更新，不存在则插入（适用于变更型数据）
- MERGE：复杂合并逻辑（自定义SQL实现）

**批量写入优化**：
- JDBC批量插入（batch size = 1000）
- 使用LOAD DATA INFILE（MySQL）或类似快速导入命令
- 临时表+RENAME方式实现原子替换

### 4.4 数据质量校验模块

#### 4.4.1 校验规则管理

**数据模型**：

```
校验规则表（data_quality_rule）
├── id: 主键
├── task_id: 关联同步任务ID
├── rule_name: 规则名称
├── rule_type: 规则类型（COMPLETENESS/FORMAT/RANGE/LOGIC/UNIQUE）
├── rule_config: 规则配置（JSON）
│   ├── field: 校验字段
│   ├── operator: 操作符（EQ/NE/GT/LT/IN/NOT_IN/LIKE/REGEX）
│   ├── value: 比对值
│   └── error_message: 错误提示
├── severity: 严重程度（ERROR/WARNING/INFO）
├── handle_strategy: 处理策略（REJECT/ALLOW/REPLACE）
├── status: 状态（ENABLED/DISABLED）
└── created_at: 创建时间
```

**规则类型详解**：

| 规则类型 | 说明 | 示例 |
|---------|------|------|
| 完整性 | 必填项校验 | 学号、姓名不能为空 |
| 格式校验 | 正则表达式匹配 | 身份证号18位，手机号11位 |
| 范围校验 | 数值/日期范围 | 成绩0-100，出生日期在合理范围 |
| 逻辑校验 | 跨字段逻辑 | 入学日期 < 毕业日期 |
| 唯一性 | 主键/业务键唯一 | 学号全校唯一 |
| 关联校验 | 外键关联存在 | 学院代码必须在院系表中存在 |

#### 4.4.2 清洗工作台

**功能描述**：人工处理校验失败的数据

**界面元素**：
- 异常数据列表：展示所有未处理的异常记录
- 筛选条件：按规则类型、严重程度、数据源筛选
- 批量操作：批量修正、批量忽略、批量重新校验
- 单条处理：
  - 查看原始值与错误原因
  - 在线编辑修正
  - 标记为"已忽略"并填写原因
- 修正历史：查看每条异常数据的处理记录

**业务规则**：
- ERROR级别异常必须处理后才能进入正式库
- WARNING级别异常可进入正式库但标记提醒
- 处理后的数据需重新触发校验流程

### 4.5 监控告警模块

#### 4.5.1 任务监控看板

**功能描述**：实时监控所有同步任务的运行状态

**界面布局**：

```
│  ┌─────────┐ ┌─────────┐    ┌───────────────────────────┐  │

```

#### 4.5.2 告警配置

**告警触发条件**：
- 任务执行失败
- 任务执行超时（超过历史平均耗时的200%）
- 数据量异常（与历史同期相比波动超过50%）
- 错误数据率超过阈值（如ERROR级异常率>5%）

**告警渠道**：
- 站内消息（系统内通知中心）
- 邮件通知
- 企业微信/钉钉/飞书机器人
- 短信（仅严重错误）

**告警内容模板**：
```
【质量监测平台】数据同步告警

告警类型：任务执行失败
任务名称：教务系统-学生表同步
数据源：正方教务系统
失败时间：2024-01-15 02:15:32
错误信息：连接超时，无法连接到数据库 192.168.1.100:3306
处理建议：
1. 检查网络连通性
2. 确认数据库服务状态
3. 查看详细日志：点击链接

请及时处理，避免影响数据时效性。
```

### 4.6 数据血缘模块

#### 4.6.1 血缘自动采集

**采集范围**：
- 同步任务级：记录数据从哪个源表到哪个目标表
- 字段级：记录标准字段来源于哪些源字段
- 转换级：记录字段经过哪些转换规则

**存储模型**：

```
血缘关系表（data_lineage）
├── id: 主键
├── lineage_type: 血缘类型（TABLE/FIELD/TRANSFORM）
├── source_node: 源节点（JSON：类型+ID+名称）
├── target_node: 目标节点（JSON：类型+ID+名称）
├── relation_type: 关系类型（DERIVED_FROM/TRANSFORMED_BY/AGGREGATED_FROM）
├── task_id: 产生该血缘的同步任务ID
├── created_at: 创建时间
└── updated_at: 更新时间
```

#### 4.6.2 血缘图谱可视化

**功能描述**：图形化展示数据血缘关系

**交互功能**：
- 节点展开/收起：点击节点展开上下游血缘
- 路径高亮：选中两个节点，高亮展示它们之间的血缘路径
- 影响分析：选中源节点，标记所有受影响的下游节点
- 版本对比：对比不同时间点的血缘图谱变化

## 5. 非功能需求

### 5.1 性能需求

| 指标 | 目标值 | 测试方法 |
|-----|--------|---------|
| 单表同步速度 | ≥10,000条/秒 | 100万条数据测试 |
| 并发任务数 | ≥20个任务并行 | 压力测试 |
| 数据延迟 | T+1（日增量） | 监控统计 |
| 查询响应时间 | 血缘查询<3秒 | 接口测试 |
| 系统可用性 | ≥99.9% | 全年统计 |

### 5.2 安全需求

| 安全维度 | 需求描述 |
|---------|---------|
| 数据传输加密 | 数据库连接使用SSL/TLS加密 |
| 数据存储加密 | 敏感配置（密码、密钥）AES-256加密存储 |
| 访问控制 | 基于RBAC的权限控制，敏感操作需二次认证 |
| 审计日志 | 所有配置变更、数据操作记录完整审计日志 |
| 数据脱敏 | 日志中不得出现明文敏感数据（身份证号、手机号） |

### 5.3 兼容性需求

| 兼容项 | 支持范围 |
|-------|---------|
| 数据库类型 | MySQL 5.7+, Oracle 11g+, SQL Server 2016+, PostgreSQL 10+ |
| 教务系统 | 正方、金智、强智、青果、自行开发等主流厂商 |
| 浏览器 | Chrome 90+, Firefox 88+, Edge 90+ |
| 操作系统 | CentOS 7+, Ubuntu 18.04+, Windows Server 2016+ |

### 5.4 可维护性需求

- 模块化设计：各数据源对接器独立，新增数据源不影响已有功能
- 配置化优先：尽量通过配置而非代码实现新数据源对接
- 文档完备：每个模块提供接口文档、部署文档、运维手册
- 监控完善：提供Prometheus指标暴露，支持接入Grafana
